# myproxy

GPUI controller for a bundled mihomo core. Canonical rules: `~/project/vibe/AGENTS.md`.

Strategy JSON under `~/Library/Application Support/myproxy/` is authoritative. Groups are source + name-contains (OR, `*` `?` wildcards) + pins − exact exclude; `name_excludes` drops automatic matches only. Empty condition groups stay empty. Schema 5 ensures a select group named **Telegram** (same sources as `default`/`PROXY`) and retargets a catch-all Telegram rule_set `via` to that group. PROCESS-NAME, DOMAIN-SUFFIX (`telegram.org` / `t.me` / …), and IP-CIDR (published DC ranges) only apply after traffic enters Mixed, System Extension, or TUN. Domain rules match HTTP(S) SNI/host (sniffer when TUN is on), not raw MTProto to DC IPs. Mixed is HTTP+SOCKS and stays available for explicit clients. Mixed and 系统接管 each have an independent inbound routing mode (`rule` / `proxy` / `global` / `direct`, default `rule`). **系统接管** on **设置** is MClash-style `NETransparentProxyProvider` (System Extension): process/`app` matchers compile into NE capture rules that pin a private loopback SOCKS listener (`proxy:` = via group); an exact app name also emits `name*` so Electron helpers (`T3 Code (Nightly) Helper`, `com.t3tools.t3code.helper`) match. If that group listener is missing, the flow uses the profile-rules SOCKS inbound instead of leaking Direct. Remaining unmatched traffic uses the same profile-rules inbound so domain/IP/MATCH still hit the mihomo strategy. macOS reports the *queried name* as the endpoint of system-resolver DNS flows, so the DNS provider relays those queries to the strategy's `nameserver` list (`dnsResolvers` in the enable request, `upstreamResolvers` in the bootstrap, schema 3) instead of dialing `<name>:53`; the original endpoint stays the conversation key and the endpoint the app gets its reply from. Dest and suffix rules do not pick a DNS relay group. Process-only pins and the profile-rules inlet do. `myproxyctl status` DNS readiness only proves the private SOCKS relay, not an end-to-end lookup. First enable asks the user to allow myproxy in **系统设置 › 通用 › 登录项与扩展**. Needs a Developer ID `.app`; release signing can embed `MYPROXY_HOST_DEVID_PROFILE` / `MYPROXY_NETWORK_EXTENSION_DEVID_PROFILE` (same pattern as MClash). TUN remains a mutually exclusive utun fallback (admin setuid). Both default off. Schema 7 adds a **规则** page 分流 preset: allowlist (`MATCH` DIRECT), GFWList (Loyalsoldier `gfw.txt` via mihomo rule-provider, list via the default group, `MATCH` DIRECT), unmatched group, or chinadirect (`GEOIP,CN,DIRECT` then `MATCH` the default group; NE does not embed an IP database). GFW installs or uninstalls as a whole and is not flattened into `rule_sets`. The **节点组** page lists cards plus a built-in **GLOBAL** selector (current member, search, switch). `global_selected` is restored on apply/connect; switching inbound to 全局 with an empty pick uses the default group so GLOBAL is not silently DIRECT. Click a card or「添加节点组」opens a modal editor (live preview, source pills, chips, pin/exclude). Group `kind` is mihomo `select`（手动选择）, `fallback`（自动切换，按列表顺序探测）, or `url-test`（延迟最低）. Fallback and url-test probe `gstatic` generate_204 every 30s (3s timeout, `max-failed-times` 2, not lazy) so a dead member yields to the next; they do not degrade to DIRECT. Pins/`include` come first in pin order as fallback/select priority; `name_excludes` still only drops automatic matches. The **规则** page lists match/via in a table: click a row to edit in the composer (进程/域名/后缀/关键字/网段), right-click for move/via/delete. Rule `via` is DIRECT / REJECT / a group or node, or `gfw:<group>`（GFWList 命中走该组，未命中直连）. When 系统接管 is on and `extension_mode=rule`, process/`app` and user domain/suffix/keyword/cidr matchers compile into NE capture rules. Process or dest `gfw:<group>` pins a dedicated GFW inlet (no `proxy:`) using only the user's matcher; listener `rule`/`sub-rules` are `RULE-SET,gfw` then `MATCH,DIRECT`. Mixed YAML still compiles dest/`gfw:` to `AND` plus `RULE-SET`, then the same condition → DIRECT. cidr+`gfw:` stays rejected at validate. Rule-provider `gfw` installs when routing is GFWList or any via is `gfw:`. NE never embeds the Loyalsoldier GFW domain list. MATCH leftover uses the profile-rules SOCKS inlet. The **总览** page lists setup steps (subscription → refresh → connect) and that rules apply only after traffic enters Mixed, 系统接管, or TUN. CLI install lives on **设置 → 命令行工具**, not a first-launch dialog. The **连接** page polls the local mihomo controller while visible (process, destination, chain, bytes, live up/down); empty when the core is disconnected. With 系统接管 on, activity overlays the real process (`relayLocalPort` ↔ `sourcePort`); right-click a row to create an app rule or change via. Column headers for 进程 / 目标 / 协议 / 走向 pick an exact current value (or 全部); 「显示直连」 is off by default so DIRECT hops stay hidden. The macOS application menu (MyProxy) lists About, Check for Updates, and Quit. The menu-bar extra left-clicks to open the window; right-click shows status plus connect or disconnect, apply, about, updates, and quit. Developer mode and launch toggles (开机默认启动 / 静默启动 / 轻量模式 / 启动时默认连接) live on **设置**, together with System Extension status, built-in bypass, optional LAN capture, and optional system HTTP/SOCKS → Mixed (restored on disconnect). Lite mode skips the main window until the menu-bar extra opens it. Levels: error / warn / info always go to `~/Library/Application Support/myproxy/myproxy.log`; debug / trace only with developer mode or `MYPROXY_DEV=1`. Lines are `HH:MM:SSZ level target message`. The 设置 page **日志** panel always shows this tail; the Host controller writes the same file. Subscription URLs are not logged. `disconnect` / `connect` wait until System Extension capture and DNS are proven down, then reclaim leftover bundled mihomo (pid file plus this app’s processes on Mixed, controller, NE SOCKS, and DNS) so an orphan cannot keep 7891/1053. If NEDNSProxy cannot be disabled, the core stays up so system DNS is not blackholed. `myproxyctl log` prints the tail. `myproxyctl tun on|off` writes the TUN flag. `myproxyctl extension on|off` writes the System Extension flag. `myproxyctl mixed-mode` / `extension-mode` set the two inbound routing modes. `myproxyctl global [name]` reads or switches the built-in GLOBAL selector. `myproxyctl routing allowlist|gfwlist|group|chinadirect` sets the rules-page fallback; `unmatched` remains a compat alias. Chinadirect emits `GEOIP,CN,DIRECT` then `MATCH` to the default group. System proxy (settings) can point macOS HTTP/HTTPS/SOCKS at Mixed and restores on disconnect. `myproxyctl export [path]` writes the current strategy JSON (default `~/Downloads/myproxy-strategy-YYYY-MM-DD.json`). `myproxyctl import <path>` replaces it after writing `strategy.json.bak-import-*` and does not apply.

Public repo: https://github.com/leaperone/myproxy. Stable Sparkle channel: `https://github.com/leaperone/myproxy/releases/latest/download/appcast.xml`. Prod and Nightly both run `generate_appcast` against previous same-channel zips for deltas (Nightly skips the `nightly` pointer tag). While Mixed is listening, in-app update checks and downloads fetch GitHub release assets through that HTTP proxy with a new CONNECT per host so the 302 to `release-assets.githubusercontent.com` does not reuse the GitHub tunnel; Sparkle reads a loopback appcast whose enclosure paths keep `.zip` / `.delta`.

Runtime safety: empty groups use an unavailable REJECT sentinel, never implicit DIRECT; UI counts and selections exclude that sentinel. RuleSet matchers remain OR conditions. Process and user dest pins keep rule-page order in the System Extension; MATCH leftover and Mixed dest/`gfw:` stay in mihomo YAML after built-in local bypasses. Saved strategy is intent, not proof of activation: report core, System Extension, and DNS separately, and use the applied runtime identity for controller requests. NEDNSProxy must not stay enabled after the DNS backend is gone; disconnect keeps the core if capture/DNS disable is unproven. Connections are Mihomo records, not an audit of all machine traffic. See README “Routing and runtime state” for the user-facing contract.


Cloud Agent VMs are Linux. `scripts/fetch-mihomo.sh` is darwin-arm64; the environment install fetches host-native mihomo into `resources/mihomo/mihomo`. Strategy on Linux is `~/.local/share/myproxy/` (`dirs::data_dir`), not `~/Library/Application Support/myproxy/`. System Extension, Sparkle, login items, and TUN setuid stay macOS-only. Use `myproxyctl` for apply/connect; the GPUI window builds here and needs `DISPLAY=:1 WGPU_BACKEND=gl LIBGL_ALWAYS_SOFTWARE=1`. Do not start the GUI or Mixed inbound from `install`.

## Runtime control ownership

The bundled macOS CLI delegates `status`, `apply`, `subscription refresh`, `connect`, and `disconnect` to the signed application through a private, same-user Unix socket. Mutating commands can open that same app in the background, suppressing launch-time auto-connect; status does not launch it and reports unobserved System Extension/DNS when the Host is unavailable. Never fall back to CLI-owned Network Extension calls after an IPC failure or replay a command after losing its reply. Pending authorization belongs to the long-lived Host. Unbundled macOS CLI writes are refused when saved or applied configuration uses System Extension. Linux keeps local CLI execution. Reuse capture only for an identical request with confirmed capture, DNS, and applied revision; DNS-stop failure must retain the core without an immediate duplicate stop in rollback.
